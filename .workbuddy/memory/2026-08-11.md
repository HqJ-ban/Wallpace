  - 系统 Python `C:\Programs\Python\Python313`（**已装齐 PySide6 6.11.1 + PyInstaller 6.21.0**）。
- 现象：双击 `build.bat` "没反应" → 因为脚本里用裸 `python`/`pip`，解析到 WorkBuddy 那套缺依赖的 Python。

  之后裸 `python`/`pip`/`pyinstaller` 都指向系统 3.13，双击可正常打包。

## git 仓库损坏 object 修复（2026-08-11）

- 仓库对象库有损坏/缺失对象：**本地 clone 不完整，历史最早处断裂**。`fb9a859`（master 上最早可达 commit）的父是 `bc80c3ac`，其祖父 `0db1da95` 缺失；`git fsck` 还报大量 broken link / missing blob。
- **commit 失败现象**：`error: invalid object <hash> for 'src/...'` + `Error building trees`。根因是某些 tracked 文件的 blob 在 `.git/objects` 里损坏了（磁盘/沙箱写入导致），git add 因 stat 缓存沿用损坏指针不重写。
- **修复法（逐个暴露的损坏 blob）**：
  1. `rm -f .git/objects/<aa>/<剩余hash>`
  2. `git update-index --force-remove <path>` 再 `git add <path>`（强制重新 hash 工作区真实内容、写新 blob）
  3. 也可用 `git ls-tree -r HEAD` 配合 `git cat-file -e` 批量扫出所有损坏 blob 一次性处理。
  4. commit 时还会因"与父 commit 算 diff 读不到旧 blob"报 `fatal: unable to read ...`，但该 fatal 不影响新 commit 落地（新 tree 已用新 blob 写好）。
- 本次修复的损坏 blob：`src/app/widgets/__init__.py`、`src/app/image_loader.py`、`src/core/image_library.py`、`requirements.txt`。最终 commit = `c067348`（含 UI 卡死修复）。
- **`git gc --prune=now` 会失败**：traverse 时撞缺失父 `0db1da95` → `fatal: Failed to traverse parents of bc80c3ac` → repack 中断。历史断裂无法在不丢历史的情况下消除。
- **沙箱 `git fetch origin` 为空**：拉不到远程补全（网络限制或远程已重写历史）。
- 结论：当前 master 5 个 commit 完好可用（开发/打包/运行都不受影响），仅 `git fsck`/`git gc` 报警。彻底干净需联网后重新 `git clone` 再 cherry-pick 修复，或接受历史截断现状。
